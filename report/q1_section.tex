\section*{Question 1 -- River Forecasting Proposal}
\addcontentsline{toc}{section}{Question 1}

\noindent\textbf{Service.} Every ten minutes, forecast the water level at the four main-river stations S1--S4 for each ten-minute step of the next hour.

\noindent\textbf{Design in one sentence.} All sources are placed on one space--time grid (places $\times$ ten-minute steps). A causal temporal convolution summarises what has happened at each place. Four rounds of \emph{upstream attention} then pass information down the river, with the travel delay learned rather than fixed. A small head predicts each station's change in level over the next hour.

\subsection*{3. Forecasting task and data specification}

\textbf{Issuance and horizon.} A forecast is issued every 10 minutes at time $t_0$ (on the :00, :10, \dots\ marks). It predicts the level at S1--S4 at the six lead times $t_0+10k$ minutes, $k=1,\dots,6$, so the one-hour horizon is covered at ten-minute resolution: a $4\times6$ output per issuance.

\textbf{History window.} The model sees the last $H=30$ steps (5 hours, $t_0-290$ min to $t_0$). This covers the slowest assumed travel and rainfall response times (A7), with margin. The actual delay inside the window is learned.

\textbf{Grid.} All inputs share one grid with $T=H+6=36$ columns ($\tau=-29,\dots,0$ past; $\tau=1,\dots,6$ future) and $P=6$ rows (Dam, S1, T1, S2, S3, S4). Each cell holds $F=6$ features: level $\ell$, level-observed flag $m_\ell$, rain $r$, rain-observed flag $m_r$, release $q$ and planned-release flag $s$. The two extra flags separate ``no rain'' from ``rain unknown'', and ``planned'' from ``measured'' release (needed in Section 5).

\textbf{Alignment across sampling times.} All sources use one ten-minute clock. A level reading goes in column $\tau$ if its timestamp is within $\pm$2 minutes of $t_0+10\tau$; otherwise the cell is missing. Rain totals (A3) are summed into the interval $(t_0+10(\tau-1),\,t_0+10\tau]$ by observation time. Releases are averaged over each interval and placed by their \emph{effective} time.

\textbf{Alignment across locations.} Values are not interpolated in space. Each source is assigned to one place row (rain via A11), and the river distances enter as features on the edges of the graph used in block~2. Unequal spacing is therefore handled through distances and learned delays, not by treating rows as evenly spaced neighbours.

\textbf{Information available at issuance.} A cell is filled only if its value is known at $t_0$: a measurement must have \emph{arrived} by $t_0$, and a release plan must have been \emph{announced} by $t_0$. Future levels and future rainfall are never available; their cells stay empty with flags set to 0. The only filled future cells are the Dam row's announced releases.

\subsection*{4. Model computations and design justification}

\textbf{Notation.} Places $p\in\{\text{Dam},\text{S1},\text{T1},\text{S2},\text{S3},\text{S4}\}$; columns $\tau\in\{-29,\dots,6\}$; stations $s\in\{\text{S1},\dots,\text{S4}\}$; lead times $k=1,\dots,6$; hidden width $d=64$. $\mathbf x_{p,\tau}\in\mathbb R^6$ is one grid cell, $\mathcal U(i)$ the set of places directly upstream of $i$ (from $\mathcal E$), and $d_{ji}$ the river distance from $j$ to $i$. Levels are standardised per station using training statistics.

\textbf{Input projection.}
\begin{equation}
\mathbf z^{(0)}_{p,\tau} = W_{\text{in}}\,\mathbf x_{p,\tau} + \mathbf e_p + \mathbf c_\tau, \qquad \mathbf z\in\mathbb R^{d},
\end{equation}
where $\mathbf e_p$ is a learned place embedding and $\mathbf c_\tau$ a time embedding (calendar features plus column position, so future columns are distinguishable).

\textbf{Block 1 -- Look back (causal dilated TCN, applied to each place with shared weights).} For layers $l=1,\dots,5$ with kernel size 3 and dilation $\delta_l=2^{l-1}$:
\begin{equation}
\mathbf z^{(l)}_{p,\tau} = \mathbf z^{(l-1)}_{p,\tau} + \mathrm{ReLU}\Big(\textstyle\sum_{a=0}^{2} A^{(l)}_a\,\mathbf z^{(l-1)}_{p,\,\tau-a\delta_l} + \mathbf b^{(l)}\Big),
\end{equation}
with zero padding before $\tau=-29$. Only columns $\le\tau$ are used (causal), and the receptive field is $1+2(1+2+4+8+16)=63\ge36$ columns, so every column can see the whole window. Set $\mathbf h^{0}_{p,\tau}=\mathbf z^{(5)}_{p,\tau}$.

\textbf{Block 2 -- Pass downstream (upstream lag attention, $R=4$ rounds, separate weights per round).} For round $r$ and each place $i$ with $\mathcal U(i)\neq\emptyset$:
\begin{align}
\mathbf q_{i,\tau} &= W_Q^{(r)}\mathbf h^{r-1}_{i,\tau}, \qquad
\mathbf k_{j,\tau'} = W_K^{(r)}\mathbf h^{r-1}_{j,\tau'} + \mathbf u^{(r)}_{\tau-\tau'} + \mathbf w^{(r)} d_{ji}, \qquad
\mathbf v_{j,\tau'} = W_V^{(r)}\mathbf h^{r-1}_{j,\tau'},\\
\alpha_{i\tau,\,j\tau'} &= \operatorname*{softmax}_{\,j\in\mathcal U(i),\ \tau'\le\tau}\!\Big(\mathbf q_{i,\tau}^{\top}\mathbf k_{j,\tau'}/\sqrt d\Big), \qquad
\mathbf m_{i,\tau} = \textstyle\sum_{j,\tau'}\alpha_{i\tau,\,j\tau'}\,\mathbf v_{j,\tau'},\\
\tilde{\mathbf h}_{i,\tau} &= \mathrm{LN}\big(\mathbf h^{r-1}_{i,\tau} + W_O^{(r)}\mathbf m_{i,\tau}\big), \qquad
\mathbf h^{r}_{i,\tau} = \mathrm{LN}\big(\tilde{\mathbf h}_{i,\tau} + \mathrm{FFN}^{(r)}(\tilde{\mathbf h}_{i,\tau})\big).
\end{align}
$\mathbf u_{\tau-\tau'}$ is a learned lag embedding and $\mathbf w d_{ji}$ a distance term. Places with no upstream neighbour (Dam, T1) keep $\mathbf h^{r}=\mathbf h^{r-1}$. Four heads are used (written as one above for clarity).

\textbf{Block 3 -- Predict ahead.} Each station reads its own representation at future column $k$:
\begin{equation}
\hat\Delta_{s,k} = g\big(\mathbf h^{4}_{s,k}\big), \qquad \hat y_{s,k} = \tilde\ell_{s,0} + \sigma_s\,\hat\Delta_{s,k},
\end{equation}
where $g$ is a two-layer MLP shared by all stations (the place embedding tells them apart), $\tilde\ell_{s,0}$ is the latest valid level at $s$, and $\sigma_s$ the training standard deviation of one-hour level changes at $s$.

\textbf{Training objective.} Weighted, masked mean squared error, as in the tutorial:
\begin{equation}
\mathcal L = \frac{\sum_{b,s,k} M_{b,s,k}\,w_{b,s,k}\,\big(\hat y_{b,s,k}-y_{b,s,k}\big)^2/\sigma_s^2}{\sum_{b,s,k} M_{b,s,k}\,w_{b,s,k}}, \qquad
w_{b,s,k} = 1 + \lambda\,\mathbb 1\big[y_{b,s,k}\ge\theta_s\big],
\end{equation}
with $M=0$ for missing targets, $\lambda=4$ (tuned on validation) and alert levels $\theta_s$ (A8). Adam, early stopping on validation error, chronological split (A1). During training, 10--20\% of cells (and occasionally a whole row) are randomly masked so the model learns to forecast with missing data. \emph{Optional extension:} $g$ outputs the 10/50/90\% quantiles, trained with pinball loss, to give a forecast range.

\textbf{Why this design.}
\begin{itemize}
  \item \emph{Upstream paths are required.} A station's own history cannot show water already on its way (companion notebook, Part 1). Block~2 gives every station a path to all upstream sources; four rounds cover the longest path, Dam$\to$S1$\to$S2$\to$S3$\to$S4.
  \item \emph{Delay must be learned, not fixed.} Travel time changes with flow (F6, A10). Attention weights are recomputed from each input, so the same model can look 50 minutes back on a calm day and 25 minutes back in a flood. A fixed convolution kernel along the river would impose one delay.
  \item \emph{Unequal spacing.} A spatial convolution treats index neighbours as equally related (notebook, Part 2). Here ``neighbour'' comes from the supplied river connectivity (F4), and distance is an explicit feature.
  \item \emph{TCN for local history.} A causal dilated TCN (Lecture 4) reaches the full 36-step window with five layers and few parameters, and captures local shape (rising limb, peak) that single-value tokens lack (Lecture 5).
  \item \emph{Announced releases on the same grid.} Covariates help only when they cover the forecast horizon (finding in PA1). Putting the plan in the Dam row's future cells lets it flow to S1 (and onward) through the same blocks.
  \item \emph{Predicting the change.} Levels are persistent over one hour; predicting $\hat\Delta$ makes persistence the default, so the network learns only rises and falls.
  \item \emph{Cost.} The graph is tiny (6 places, 5 edges), so the quadratic cost of attention is negligible (see Section~5).
\end{itemize}

\textbf{How each source reaches each forecast.}
\begin{itemize}
  \item \emph{Reservoir releases} (past and planned) enter at the Dam row and reach S1 in round~1, S2 in round~2, S3 in round~3 and S4 in round~4.
  \item \emph{Upstream conditions}: each station attends to its upstream neighbours' histories, which already contain everything further upstream from earlier rounds.
  \item \emph{Monitored tributary}: T1 is a direct upstream neighbour of S2, and so indirectly of S3 and S4.
  \item \emph{Rainfall}: R1 enters at S2's row (local inflow); R2 enters at S3's row as the proxy for the unmonitored tributary (A11, A12). The TCN learns the delay between rain and river response.
\end{itemize}

\subsection*{5. Operation and exceptional conditions}

\textbf{(i) Missing observations.} A missing level or rain value is set to 0 with its flag ($m_\ell$ or $m_r$) set to 0, so the model can tell ``missing'' from ``zero''. Random masking during training (Section 4) teaches the model to use upstream and neighbouring rows instead. If a station's current level is missing, the forecast is anchored on its latest valid value $\tilde\ell_{s,0}$ and marked lower-confidence. Missing targets are excluded from the loss ($M=0$). If a whole station has been missing for more than two hours, forecasts are still issued but flagged to operators, and the quantile range widens.

\textbf{(ii) Delayed observations.} The forecast is issued on time at $t_0$ with whatever has arrived; values not yet received are treated as missing. A reading is placed by its \emph{observation} timestamp, but used only if its \emph{arrival} time is $\le t_0$. When a late reading arrives it fills its cell for the next issuance; because one forecast takes milliseconds, the current forecast can also be re-issued at once. Training simulates delays using the observed delay distribution (A4), so the model sees the same gaps it will meet in operation.

\textbf{(iii) Announced future releases.} The latest schedule announced by $t_0$ is placed in the Dam row's future columns ($\tau=1,\dots,6$) by effective time, with $s=1$. A schedule announced after $t_0$ is not used, even if it takes effect earlier. With no announcement, the current rate is assumed to continue (A14). Training uses the plans as they were announced at each past $t_0$ (A6), not the releases that later occurred.

\textbf{(iv) Scheduled vs.\ actual releases.} Once a release is recorded, its past cell holds the actual value with $s=0$, overriding the plan. Because training pairs announced plans with the levels that followed, the model learns how far plans can be trusted, through flag $s$. When the actual release has departed from the plan by more than a set threshold over the last 30 minutes, operators are alerted and the forecast range is widened. Since a forecast is cheap, operators can also run ``what-if'' forecasts for alternative release plans.

\textbf{Feasibility every 10 minutes.} One forecast processes $6\times36=216$ cells. The TCN costs about $216\times5\times3\times64^2\approx1.3\times10^{7}$ multiply--adds; the four attention rounds about $4\times36\times72\times64\times2\times4\approx5\times10^{6}$; the model has roughly $2\times10^{5}$ parameters. This is well under 10 ms on a standard CPU, and data alignment is a few database queries, so a ten-minute cycle leaves a large margin. Training is done offline and repeated periodically (e.g.\ monthly or after a major flood).
